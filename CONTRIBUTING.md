# Contributing

Thanks for considering a docs PR.

## What to contribute

- Typo fixes, factual corrections, broken links: open a PR directly.
- New pages or restructured navigation: open an issue first to discuss.
- Code samples, recipes, integration notes: PR welcome. Keep examples runnable.

## Style

- No em dashes. Use commas, colons, periods, or parentheses.
- No exclamation marks.
- No corporate jargon. Plain technical English.
- Code blocks always specify language.
- Headings use sentence case.

## Local preview

```bash
mintlify dev
```

## Frontmatter

Each MDX page has a frontmatter block:

```yaml
---
title: "Page title"
description: "One-line description for search and link previews"
---
```

## Commits

Conventional-commit style is fine but not required. One logical change per commit.
